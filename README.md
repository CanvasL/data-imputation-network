# 数据归算网络（Data Imputation Network, DIN）

> 一个让数据像论文一样被引用、像代码一样被策展、并让每一次策展都产生收益的数据经济协议。

## 是什么

DIN 是一个数据经济基础设施，回答一个根本问题：**数据值多少钱？**

它让数据像论文一样拥有引用关系，让数据贡献者持续分享数据产生的收益：

- 贡献数据的人，获得长期收益；
- 整理数据的人，获得加工收益；
- 使用数据的人，能订阅到高质量数据；
- 数据的价值，由市场用真金白银自然发现。

## 第一性原理：归算价值论

**数据没有内在价格，只有归算价格；价格的唯一来源是终端消费者的支付意愿。**

数据是归算理论（imputation）与派生需求（derived demand）最纯粹的样本：

- 成本与价值零相关——花一个亿采集的数据可能一文不值，偶然的洞察可能价值连城；
- 非竞争性商品——复制边际成本为零；
- 价值完全上下文依赖——同一份数据对不同使用者价值天差地别。

因此数据价值无法由内在属性或成本决定，只能由下游归算而来：

$$Price(Dataset) = \sum_{t} \frac{\text{未来下游订阅现金流}_t}{(1+r)^t}$$

### 三个推论

1. **挂价 ≠ 价值**：真实价值 = 事后被下游确认的已实现支付流，价值自我揭示；
2. **质量市场化**：付费本身就是质量的市场信号；
3. **外部付费者是网络成立的必要条件**：纯内循环交易建立不起真实价值，因为缺少锚定价格的外部终点。

## 核心机制：归算图

协议只有两个基本动作：**提供（Contribute）** 与 **订阅（Subscribe）**。

关键发现：**消费和策展，本质都是订阅**——"消费者"和"策展人"在协议中是同一个角色：订阅者。区别只在于拿到数据之后做什么，对协议而言都是"订阅"。

每一次派生都记录为一条携带真实货币支付的谱系边，谱系图因此成为一张**支付加权图**：

- 每条 `Dataset → Dataset`（派生）边，都是一次真实付费订阅；
- 每条边都可审计：谁、付了多少钱、给谁；
- 数据价值 = "有多少真金白银，愿意基于它继续策展"。

与论文引用的本质区别：论文引用是免费的、可以刷的；这里的引用**带着钱**，无法被零成本刷出来。

### 价值回流

订阅收入沿血缘图向上游回流（示意分配：上游贡献 70% / 本层策展 20% / 协议基金 10%）。收益在循环内闭合：你付给上游的钱，会在你向下游策展时挣回来。

### 网络留存

网络不靠"锁"留人，靠"参与才能受益"：

- **收益回溯 = 留住贡献者的锁**——留在网内就持续分成，脱网现金流立刻中断；
- **归算图 = 留住所有人的场**——声誉、排名、价值发现只存在于网内；
- **新鲜度 + 质量信号 = 留住订阅者的钩**——订阅交付更新，一次性拷贝是过期快照。

### 冷启动

数据集可以 **0 元起步**：免费试用揭示价值，第一个真正付费的下游是价值锚点。价值只会来自真实终端消费者的支付意愿，纯"数据到数据"的内循环交易建立不起真实价值。

## 架构

| 层 | 目录 | 职责 | 技术绑定 |
|---|---|---|---|
| 协议核心 | `din-core` | 数据模型 / 归因 / 归算 / 签名 / 事件源引擎 | 无（存储无关 SDK） |
| 存储 | `din-store-memory` / `din-store-sqlite` | `EventStore` 端口适配器 | 可插拔 |
| 节点 | `din-node` | HTTP API + 启动预检 | axum + SQLite |
| 前端 | `din-frontend` | 价值地图 / 数据集面板 / 事件表单 | React + Vite |

## 快速开始

前置：Rust、Python 3、Node.js。

```bash
# 1. 启动节点（默认监听 127.0.0.1:8080）
cargo run -p din-node -- --db data/din.db --addr 127.0.0.1:8080

# 2.（可选）灌入一个示例谱系网络
python3 din-frontend/seed.py

# 3. 启动前端
cd din-frontend && npm install && npm run dev
# 打开 http://localhost:5173
```

### 节点 API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/health` | 健康检查 |
| POST | `/agents` | 创建身份（Ed25519 密钥对） |
| POST | `/events` | 提交事件（contribute / subscribe） |
| GET | `/datasets` | 列出所有数据集 + 归算值 |
| GET | `/datasets/:id/value` | 查询单个数据集归算值 |
| GET | `/graph` | 查看归算图（边含 price / alpha） |

## 协议要点

### 数据模型

```
Dataset { id, owner, schema, version, state_hash }   // id 内容寻址：同一内容 = 同一 id
Edge    { parent, child }                            // 派生边（有向无环图，防环）
Payment { edge, amount, paid_by, received_by }
```

### 事件日志

追加写、不可变；`prev_hash` 链式防重排；`payload_hash` 校验完整性；事件类型：
`contribute` / `subscribe` / `payment` / `attribute` / `challenge` / `resolve`。

### 归因与归算

- **归因规则**：协议留存 `mu`（不可回收，防自我交易）+ 上游归因 `lambda` + 策展边际 `1 - lambda`；
- **归算算法**（拓扑序，$O(|V|+|E|)$）：

$$V(v) = R_v + \sum_{v' \in \mathcal{C}(v)} \alpha_{v,v'} \left[ P_{v,v'} + V(v') \right]$$

- **唯一解**：$V = (I - A)^{-1}b$（DAG 上幂零矩阵，保证任何实现算出一致结果）。

### 身份与账本

- 身份 = `AgentID` 绑定 Ed25519 密钥对，每个事件必须签名；
- 账本要求（不指定具体技术）：追加写不可变、可审计重放、可导出、防重排。
